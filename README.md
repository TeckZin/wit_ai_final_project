# *** AI PROJECT ***

## A* Solver — Maze & 8-Puzzle (browser edition)

A generic A* search implementation applied to two classic search problems —
a randomly generated maze and the 8-puzzle — rendered on an HTML5 `<canvas>`
in the browser. No native modules, no compiled dependencies: just Vite +
the browser's built-in Canvas API.

```
                                     keyboard input, menu/maze/puzzle screens
```

## How it works

`src/solver/astar.ts` exports a single generic `astar<State>(problem)` function
built around a binary min-heap open set. It's agnostic to what "State" means —
it just needs a `Problem<State>` describing the start state, a goal check,
neighbor generation with costs, a heuristic, and a way to hash states for
visited-tracking. Both the maze and the puzzle plug into this same function
through their own `Problem<State>` implementations.

- **Maze** (`app/maze/maze.ts`): a 15×15 grid carved with randomized DFS
  (recursive backtracker), which guarantees a unique, fully-connected,
  loop-free path between any two cells — i.e. always solvable. The
  heuristic is Manhattan distance to the goal cell.
- **8-puzzle** (`app/puzzle/puzzle.ts`): the classic sliding tile puzzle,
  generated by scrambling backward from the goal state (sidestepping the
  50%-unsolvable permutation-parity problem). Supports two interchangeable
  heuristics — misplaced tiles and Manhattan distance — so you can compare
  nodes-expanded/runtime between them.

`app/web/main.ts` ties it together: it draws a menu, and on M or P it
generates a fresh maze/puzzle, runs `astar()` on it, and animates the
returned path frame by frame on the canvas.

## Running it

```bash
npm install
npm run dev
```

Vite prints a local URL (usually `http://localhost:5174`) — open it in your
browser.

**Controls:** `M` — solve a new maze · `P` — solve a new 8-puzzle ·
`Backspace` — back to the menu

## Why no native dependencies

An earlier version of this used `@kmamal/sdl` + `canvas` for a real native
window, but `canvas` compiles a native addon against Cairo/Pango and can fail
to build depending on your Node version and system libraries. Since none of
the actual solving logic depends on Node or a native window, moving rendering
to the browser's built-in Canvas 2D API removes that whole class of problem —
`vite` and its dependencies ship as prebuilt binaries, so `npm install` just
works.
